# U-Net 踩坑第二篇：从“有影像就能推理”到制作可比较的训练样本

## 这次踩到的坑：模型结构不是已经会识别的模型

在第一篇中，我准备了西安高分辨率影像和 Sentinel-2 / 祁连影像，也写好了 U-Net、ResUNet、Attention U-Net、U-Net++、TransUNet、Swin-UNet 的推理入口。最开始的想法很自然：**有数据、有模型代码，直接运行推理，应该就能得到建筑和植被提取结果。**

实际执行时，程序报错：找不到模型权重文件。

```text
models/Unet/resunet_building.pth 不存在
```

这不是简单的路径问题，而是对“模型”和“权重”理解不完整。U-Net、ResUNet、Attention U-Net 等只是网络结构，类似不同款式的空白大脑；它们定义了数据怎样在卷积层、跳跃连接或注意力层之间流动，但刚创建时内部参数都是随机数，并不认识建筑、植被或道路。

真正能用于推理的是下面的组合：

```text
模型结构 + 训练后的权重 = 可用于特定任务的分割模型
```

权重通常保存为 `.pth` 文件。它记录了模型从大量“影像—正确答案”样本中学习到的参数。没有匹配的权重，不能得到可信的建筑或植被结果；即便为了测试流程而临时使用随机参数，输出也没有业务意义。

## 为什么不能随便下载一个 U-Net 权重

网上确实有很多 U-Net 权重，但每套权重都和其训练任务绑定。例如：

| 权重训练数据 | 适合的任务 | 是否能直接用于本项目 |
|---|---|---|
| 医学 CT 器官标签 | 器官分割 | 不可以 |
| 航拍建筑物标签 | 建筑提取 | 可作为建筑基线，但仍要检查波段、分辨率和地区差异 |
| Sentinel-2 土地覆盖标签 | 土地覆盖 / 植被分类 | 可作为植被基线，但需确认类别定义 |
| 本项目西安影像和人工标签 | 西安建筑、植被提取 | 最匹配 |

同样叫 ResUNet 的模型，输入波段可能不同，输出类别可能不同，网络宽度也可能不同。一个医学图像的二分类权重，不能直接装入遥感建筑模型；一个六分类 U-Net++ 权重，也不能直接装入二分类 ResUNet。即使代码勉强运行，预测结果也不可靠。

因此，如果目标是对六种 U-Net 变体做公平对比，最可靠的路径不是“给每个模型随便找一个权重”，而是用**同一套本地样本**分别训练六种结构，然后在同一测试区进行推理比较。

## 本项目真正要做的任务：像素级分类，而非整图分类

这里所说的图像分类，不是输入一张影像后只输出“这是一片城区”或“这是一片植被”的单一类别，而是语义分割（像素级分类）：

```text
输入：西安或 Sentinel-2 的一幅遥感影像
输出：与输入同尺寸的分类栅格

0 = other（其他地物）
1 = building（建筑）
2 = vegetation（植被）
```

从这个分类栅格中分别取出值为 `1` 和 `2` 的像元，就得到建筑掩膜和植被掩膜。后续还可以把建筑掩膜矢量化为建筑面。

采用统一的三分类标签，比“建筑训练一套、植被训练一套”更适合当前的对比实验：每个网络只需要训练一次，就能同时输出建筑和植被；六种模型的输入、类别和测试条件也完全一致。

## 两组影像不要直接混在一个实验中

当前准备的数据包括西安高分辨率 RGB 影像，以及 Sentinel-2 / 祁连影像。两者的空间分辨率、成像特征和地物纹理相差很大，不能不加区分地混到同一个训练集里。

建议拆成两组独立实验：

| 实验 | 数据特点 | 重点类别 | 对比目的 |
|---|---|---|---|
| 实验 A | 西安高分 RGB | 建筑、城市植被、其他 | 比较模型对屋顶边界、密集建筑和阴影的适应性 |
| 实验 B | Sentinel-2 / 祁连 | 植被、建成区、其他 | 比较模型对中分辨率土地覆盖的适应性 |

每一组实验中，六个模型必须使用同样的训练、验证和测试样本。这样对比出来的差异才主要来自模型结构，而不是样本或场景不同。

## 是否需要把整幅影像全部绘制完成

不需要，也不建议一开始就标完整幅西安或祁连影像。整图标注成本极高，而且前期类别标准、裁切尺寸和标签处理方式往往还会调整。

推荐的方式是：从大影像中选择一批有代表性的小区域，裁切成样本块；但**一旦选中一个样本块，就应尽量完整标注该样本块内的目标。**

```text
整幅影像
  ↓ 按场景抽取小区域
影像样本块
  ↓ 对样本块做完整多边形标注
影像块 + 分类标签块
  ↓
训练 / 验证 / 测试样本
```

西安样本应尽量覆盖：

- 高层住宅、低矮民房、工业厂房、密集居民区；
- 公园、行道树、草地；
- 道路、停车场、裸地、水体；
- 建筑阴影、屋顶反光、施工地等容易混淆的场景。

Sentinel-2 / 祁连样本应尽量覆盖：

- 高、中、低覆盖度植被；
- 林地、草地、农田；
- 裸地、水体、道路、居民地；
- 山地阴影、不同坡向和不同亮度的区域。

初次验证流程时，可以先制作 10 个左右样本块。正式对比建议每组至少准备：

| 用途 | 建议数量 | 说明 |
|---|---:|---|
| 训练 | 60–100 个样本块 | 覆盖大多数典型场景 |
| 验证 | 15–20 个样本块 | 用于选择训练轮次和参数 |
| 测试 | 20–30 个样本块 | 不参与训练，只用于最终比较 |

样本块可以统一裁切为 `512 × 512` 像素；显存较小时，训练阶段再裁为 `256 × 256` 像素。对 Sentinel-2 而言，同样的像素尺寸覆盖的实际地面范围更大，这是正常的；实验 A 和实验 B 本来就是两组独立对比。

## 样本应该画矩形还是多边形

这里有两个容易混淆的“图形”：

| 图形 | 用途 | 应该是什么形状 |
|---|---|---|
| 样本块范围 | 从大图中裁切训练影像 | 矩形 |
| 建筑、植被标签 | 告诉模型目标在哪里 | 贴合地物边界的多边形 |

因此，**裁切范围用矩形，地物标签用多边形。**

建筑物应沿可见屋顶外轮廓绘制多边形，不应简单画一个大矩形。用矩形会把屋顶周围的道路、阴影、空地一起误标成建筑，模型也会学习到这种错误关系。

植被同样应按可见的树冠、草地、林地或农田边界绘制多边形。不要把明显的道路、水体或建筑包含在植被面中。

Sentinel-2 分辨率较低时，逐栋建筑往往只占几个像元，标注逐栋屋顶没有意义。这种情况下，可将连续建成区标为“building / built-up”，将连续植被覆盖区标为“vegetation”。标注粒度必须与影像能分辨的空间尺度一致。

## 如何在 GIS 软件中制作矢量样本

以下以 QGIS 或 ArcGIS 为例，核心步骤相同。

### 1. 建立标注工程

加载原始 TIFF，并确认工程坐标系与影像一致。当前影像已经是 Web Mercator，即 `EPSG:3857`，标注图层也应使用该坐标系。

为每一组实验建立一个 GeoPackage，推荐如下：

```text
Unet/labels/
  xian_labels.gpkg
  qilian_labels.gpkg
```

在每个 GeoPackage 中创建面图层，例如 `landcover`。推荐字段：

| 字段名 | 类型 | 示例 | 说明 |
|---|---|---|---|
| `class_id` | 整数 | 1 | 0=other，1=building，2=vegetation |
| `class_name` | 文本 | building | 类别名称 |
| `source` | 文本 | manual | 可选，记录标注来源 |
| `note` | 文本 | roof-shadow | 可选，记录疑难场景 |

### 2. 先定义标注标准，再开始绘制

在大量标注前，先写清楚以下规则，并始终保持一致：

- 建筑标屋顶边界，还是建筑物底座边界？高分 RGB 影像通常选择屋顶可见范围；
- 行道树、灌木、草坪、农田是否全部归为 vegetation？建议是；
- 阴影覆盖的建筑如何处理？边界明确时按建筑标；无法判断时作为 ignore；
- 施工地、裸地、道路、水体统一归为 other；
- 建筑与树冠重叠时，按影像可见地物标注，不人为推测被遮挡部分。

这一步看起来很细，但决定了模型最终学到的“建筑”和“植被”分别是什么。

### 3. 按样本块逐块绘制

先画一个矩形范围作为样本块，例如 `512 × 512` 像素覆盖的地面范围。然后在此范围内：

1. 绘制所有清晰可见的建筑多边形，设置 `class_id=1`；
2. 绘制所有清晰可见的植被多边形，设置 `class_id=2`；
3. 剩余的道路、水体、裸地等区域自动视为 `other`；
4. 检查面之间是否重叠、是否存在明显错位。

不要只画样本块内的两三个建筑，就让其他尚未绘制的建筑自动变成背景。因为这些未绘制建筑会在标签中被当成 `other`，模型将学到“某些建筑是背景”的错误信息。

## 标注量不足时：使用忽略区域，而不是错误背景

人工标注时间有限时，可以采用“部分标注 + 忽略区域”。此时标签增加一个值：

```text
0   = other
1   = building
2   = vegetation
255 = ignore（未确认或不准备标注的区域）
```

值为 `255` 的像元不会参与损失计算，避免模型把未知目标学成背景。需要注意：训练程序必须显式支持 `ignore_index=255`；不能把它当成普通类别。

即使使用 ignore，也建议至少挑选一部分样本块进行完整标注。完整样本对稳定训练和真实评估非常重要。

## 将矢量样本转换为训练标签栅格

U-Net 训练时不能直接读取多边形作为答案，通常需要将多边形栅格化为单波段标签 TIFF。

假设一张影像样本为：

```text
xian_001.tif
```

则对应标签应为：

```text
xian_001_mask.tif
```

标签 TIFF 的每个像元储存类别值：

```text
0 = other
1 = building
2 = vegetation
255 = ignore（如使用）
```

栅格化时最重要的不是文件名，而是标签栅格和影像必须严格对齐：

```text
CRS 一致
宽度、高度一致
仿射变换一致
左上角位置一致
像元大小一致
```

最安全的方式是在 GIS 中以每个影像样本块为模板栅格化：使用影像样本块的范围、分辨率和像元网格创建标签，而不是手动填写一个“差不多”的分辨率。

## 训练、验证、测试必须按空间区域隔离

把同一街区相邻的小块随机分到训练集和测试集，会造成空间泄漏。相邻影像纹理几乎一样，模型即使没有真正泛化，也会在测试集上得到虚高精度。

正确方式是按地理区域切分。例如：

```text
西安东部区域     → 训练集
西安中部区域     → 验证集
西安西部区域     → 测试集
```

祁连实验也应将不同山谷、坡向或地块分别分配到训练、验证和测试集。测试区在整个制作过程中不参与类别规则调整、参数选择和模型训练。

推荐的数据目录如下：

```text
Unet/
  data/
    xian/
      train/
        images/
        masks/
      val/
        images/
        masks/
      test/
        images/
        masks/
    qilian/
      train/
        images/
        masks/
      val/
        images/
        masks/
      test/
        images/
        masks/
  labels/
    xian_labels.gpkg
    qilian_labels.gpkg
```

同名影像与标签必须一一对应，例如：

```text
images/xian_001.tif
masks/xian_001_mask.tif
```

## 六模型如何做公平比较

样本完成后，对每一组实验分别训练：

```text
U-Net
ResUNet
Attention U-Net
U-Net++
TransUNet
Swin-UNet
```

六个模型之间只改变网络结构，以下条件保持一致：

| 项目 | 是否保持一致 |
|---|---|
| 训练、验证、测试样本 | 必须一致 |
| 类别定义和标签编码 | 必须一致 |
| 输入波段和归一化方法 | 必须一致 |
| 输入切片大小 | 必须一致 |
| 数据增强方式 | 尽量一致 |
| 训练轮数、学习率策略 | 尽量一致 |
| 测试区域 | 必须一致 |
| 阈值、最小斑块过滤等后处理 | 必须一致 |

最终不只比较“哪张图看起来更好”，还应记录：

```text
building IoU、vegetation IoU、mIoU
building F1、vegetation F1、Dice
训练耗时
单张或整图推理耗时
显存占用
建筑与植被结果图
```

## 下一步：从小规模样本开始验证规范

最稳妥的第一步，不是马上标几百个样本，而是：

1. 从西安影像裁切 5–10 个具有代表性的样本块；
2. 用多边形完整绘制建筑与植被；
3. 栅格化为三分类标签；
4. 检查影像和标签是否像元级对齐；
5. 先跑通一轮 U-Net 训练和推理；
6. 确认标签标准和流程没有问题后，再扩大到正式样本数量，并训练六个模型做对比。

这样做可以把“标注标准不一致”“标签错位”“类别编码错误”“训练集与测试集泄漏”等常见问题尽早发现，避免后期返工。
