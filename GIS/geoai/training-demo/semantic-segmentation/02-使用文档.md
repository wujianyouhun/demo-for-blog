# 从零开始——手把手教你运行语义分割训练

这篇文档将带你从零开始，一步步把语义分割训练项目跑起来。无论你是第一次接触深度学习的初学者，还是有一定经验但想快速上手的开发者，都能在这里找到清晰的指引。我们会从环境搭建讲起，覆盖目录结构、数据准备、训练运行、结果解读，最后附上常见问题的排查方法，确保你能顺利走完整个流程。

## 环境准备——搭建你的深度学习工作台

运行本项目需要一套基本的软件环境。最核心的依赖是 Python 和 PyTorch，前者是编程语言，后者是深度学习框架。我们推荐使用 Python 3.11，因为它在性能和兼容性之间取得了很好的平衡。

首先是 Python 的安装。建议使用 Anaconda 或 Miniconda 来管理 Python 环境，这样可以方便地创建独立的虚拟环境，避免不同项目之间的依赖冲突。在命令行中执行以下命令创建一个名为 geoai 的虚拟环境：

```bash
conda create -n geoai python=3.11 -y
conda activate geoai
```

接下来安装 PyTorch。PyTorch 的安装需要匹配你电脑的硬件配置，特别是显卡类型。如果你有一块 NVIDIA 显卡（比如 RTX 3050、RTX 4060 等），强烈建议安装支持 CUDA 的版本，因为 GPU 训练速度比 CPU 快几十倍。访问 PyTorch 官网 pytorch.org 可以获取最新的安装命令，一个典型的 GPU 版本安装命令如下：

```bash
# CUDA 11.8 版本（适用于大多数 NVIDIA 显卡）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118

# CUDA 12.1 版本（适用于较新的 RTX 40 系列显卡）
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu121
```

如果你没有 NVIDIA 显卡，也不用担心。PyTorch 的 CPU 版本可以正常运行本项目，只是训练速度会慢很多——在 GPU 上几分钟就能完成的训练，在 CPU 上可能需要一两个小时。CPU 版本的安装命令更简单：

```bash
pip install torch torchvision
```

除 PyTorch 之外，项目还依赖几个常用的科学计算库。以下是一条命令安装所有依赖：

```bash
pip install numpy matplotlib pillow rasterio
```

其中 numpy 用于数值计算，matplotlib 用于绘制训练曲线和可视化结果，pillow 用于加载图片文件，rasterio 用于处理 GeoTIFF 格式的地理空间数据。值得注意的是，rasterio 是可选的——如果安装失败，程序会自动跳过 GeoTIFF 输出功能，其他功能不受影响。安装 rasterio 时如果遇到问题，可以尝试通过 conda 安装：`conda install rasterio`。

安装完成后，可以用一个简单的 Python 脚本来验证环境是否就绪：

```python
import torch
print(f"PyTorch 版本: {torch.__version__}")
print(f"CUDA 可用: {torch.cuda.is_available()}")
if torch.cuda.is_available():
    print(f"GPU 型号: {torch.cuda.get_device_name(0)}")
    vram = torch.cuda.get_device_properties(0).total_mem / 1024**3
    print(f"显存大小: {vram:.1f} GB")
```

## 目录结构——项目文件一目了然

解压项目后，你会看到如下目录结构。理解这个结构有助于你知道"什么东西放在哪里"，方便后续的数据替换和结果查看。

```
semantic-segmentation/
├── scripts/
│   └── train.py           # 核心训练脚本（所有代码都在这里）
├── data/                   # 数据目录（运行后自动创建）
│   ├── train/
│   │   ├── images/        # 训练影像
│   │   └── labels/        # 训练标签
│   └── val/
│       ├── images/        # 验证影像
│       └── labels/        # 验证标签
├── models/                 # 模型权重（训练后自动创建）
│   └── best_unet.pth      # 最优模型权重
└── outputs/                # 输出结果（训练后自动创建）
    ├── segmentation_results.png  # 推理可视化对比图
    └── training_curves.png       # 训练损失和精度曲线
```

这种"一切自动创建"的设计让初学者不用手动建文件夹、不用提前准备数据。第一次运行时，程序会检测到 data 目录不存在或为空，自动触发合成数据生成器，在 `data/train` 和 `data/val` 下生成训练和验证用的合成样本。

## 运行方式一：合成数据快速体验

这是最简单的运行方式，适合第一次接触项目、想快速看到效果的同学。不需要下载任何数据集，只需要确保 Python 环境就绪，然后执行一条命令：

```bash
cd semantic-segmentation
python scripts/train.py
```

程序启动后会自动执行以下流程：首先检查 `data/train/images` 目录是否存在且包含数据文件，如果没有，就自动生成200张合成训练图片和50张合成验证图片。然后构建 U-Net 模型、启动训练循环、保存最优权重、最后生成可视化结果。整个过程中你会在终端看到实时的训练日志输出。

合成数据的训练过程通常很快。在 NVIDIA RTX 3050 6GB 显卡上，30个 epoch 的训练大约需要5-10分钟。如果你用的是 CPU，可能需要30分钟到1小时。训练完成后，打开 `outputs/` 目录，你会看到两张图片：`segmentation_results.png` 展示了模型在验证集上的分割预测对比，`training_curves.png` 展示了训练过程中损失值和 mIoU 指标的变化曲线。

## 运行方式二：使用 LoveDA 真实数据

当你通过合成数据熟悉了项目流程后，就可以尝试使用真实的 LoveDA 数据集了。完整的 LoveDA 数据集可以从官方 GitHub 仓库下载：https://github.com/Junjue-Wang/LoveDA 。

下载完成后，你需要按照以下结构组织数据文件：

```
data/
├── train/
│   ├── images/    # 放入训练影像（.png 或 .tif 格式）
│   └── labels/    # 放入对应标签（单通道图像，像素值为 0-6）
└── val/
    ├── images/    # 放入验证影像
    └── labels/    # 放入对应标签
```

标签文件中的像素值需要对应到 LoveDA 的7个类别：0=背景、1=建筑、2=道路、3=水体、4=森林、5=农田、6=植被。如果原始标签的编码方式不同（比如 LoveDA 原始数据中标签从1开始而非从0开始），需要做一个简单的映射处理。准备好数据后，删除已生成的合成数据（或将其备份），直接运行 `python scripts/train.py` 即可。程序会自动检测到 data 目录下已有真实数据，跳过合成数据生成步骤，直接加载你的数据进行训练。

真实数据的训练效果远好于合成数据。在 LoveDA 上训练30个 epoch，mIoU 通常能达到0.45-0.55的范围（合成数据上由于特征过于简单，mIoU 可能很快接近0.85以上，但这不代表模型在真实场景下的泛化能力）。

## 运行方式三：使用你自己的数据

如果你有自己采集的遥感影像数据，也可以用这个项目来训练。关键是保证数据格式正确：影像应该是 RGB 三通道的图片（.png、.jpg 或 .tif 格式），标签应该是与影像尺寸相同的单通道图像，像素值从0到6代表7个类别。

一个常见的做法是先用标注工具（如 Labelme、QGIS 等）在原始遥感影像上手工标注地物类别，导出为标签图片，然后按比例划分为训练集和验证集（建议8:2或7:3的比例），放入对应的目录中。

如果你的数据类别与 LoveDA 不同（比如只有5类或者类别编号不同），需要修改 `Config` 类中的 `num_classes` 参数，并确保标签值在 0 到 `num_classes-1` 的范围内。代码中有自动裁剪标签值的保护机制：

```python
# 确保标签值在有效范围内
label = np.clip(label, 0, Config.num_classes - 1)
```

## 训练参数配置

所有的训练超参数都集中在 `Config` 类中管理，你可以根据自己的硬件条件和需求灵活调整。以下是最常修改的几个参数及其影响：

`batch_size` 控制每次送入模型处理的图片数量。数值越大，训练越稳定，但需要更多的显存。如果你的显卡显存只有4-6GB，建议将 batch_size 从4降低到2。如果显存有6GB以上，可以尝试增加到8以加速训练。

`epochs` 设置训练的总轮数。对于合成数据，15-20个 epoch 就足够了；对于真实 LoveDA 数据，建议设置30-50个 epoch。项目内置了早停机制（`patience=8`），如果验证集上的表现连续8个 epoch 不再提升，训练会自动停止，所以你不用担心设太多 epoch 导致过拟合。

`lr`（学习率）决定了模型参数更新的步长。默认的 1e-4（即0.0001）是一个比较保守但稳定的值。如果你觉得训练太慢，可以尝试提高到 3e-4；如果训练不稳定（loss 忽高忽低），则应该降低到 5e-5。

```python
class Config:
    img_size    = 256      # 输入图像尺寸
    num_classes = 7        # 类别数
    batch_size  = 4        # 批大小
    epochs      = 30       # 训练轮数
    lr          = 1e-4     # 初始学习率
    patience    = 8        # 早停耐心值
```

## 如何解读训练输出

训练运行后，终端会不断输出日志信息。理解这些信息的含义对于判断训练是否正常至关重要。

每个 epoch 结束后，你会看到类似这样一行输出：

```
Epoch 05/30 | Train Loss: 1.2345 | Val Loss: 1.3456 | Val mIoU: 0.4567 | Val OA: 0.7234 | LR: 0.000095 | Time: 45.2s
```

其中 `Train Loss` 是训练集上的平均损失值，`Val Loss` 是验证集上的损失值，`Val mIoU` 是验证集上的平均交并比（核心指标），`Val OA` 是总体精度，`LR` 是当前学习率，`Time` 是这个 epoch 的耗时。

训练过程中你应该关注的几个关键信号：训练损失和验证损失都应该呈现总体下降的趋势（偶尔波动是正常的），mIoU 应该逐步上升。如果训练损失持续下降但验证损失开始上升，说明模型出现了过拟合——它在训练数据上"死记硬背"，但在新数据上表现变差了。这时早停机制会发挥作用，在适当的时机终止训练。

学习率的变化遵循余弦退火策略——从初始值开始平滑下降，到训练末期趋近于初始值的1%。这种策略的好处是训练初期用较大的学习率快速收敛，后期用较小的学习率精细调优，比固定学习率效果更好。

## 如何查看推理结果

训练完成后，打开 `outputs/segmentation_results.png`，你会看到一张四列多行的可视化图。每一行对应一个验证样本，四列分别展示：原始影像（模型看到的输入）、真值标签（人工标注的正确答案）、模型预测（模型的输出）、叠加对比（将预测结果半透明覆盖在原图上）。

通过对比真值标签和模型预测这两列，你可以直观地看出模型的分割精度：哪些类别分得准、哪些类别容易混淆、边界是否清晰。叠加对比列则可以帮你判断分割边界是否与真实地物吻合。如果某个类别的区域被大面积错误分类（比如水体被识别成了建筑），可能说明训练数据中该类别的样本太少，需要增加数据平衡性。

`outputs/training_curves.png` 包含两个子图：左图是损失曲线（训练损失和验证损失随 epoch 的变化），右图是精度曲线（验证 mIoU 随 epoch 的变化）。健康的训练曲线应该是：损失曲线平滑下降且训练损失略低于验证损失，精度曲线稳步上升并趋于平稳。

## 常见问题排查

**CUDA 内存不足（Out of Memory）**：这是最常见的问题。当你的显卡显存不足以容纳当前的 batch_size 和模型时，PyTorch 会报 OOM 错误。解决方案是按优先级尝试：将 batch_size 减半（从4降到2，再从2降到1）；减小 img_size（从256降到128）；关闭不必要的程序释放显存。

**数据找不到（FileNotFoundError）**：如果程序报错说在 `data/train/images` 中未找到任何数据文件，请检查目录结构是否正确。合成数据应该已经自动生成，如果没有，可能是之前的运行异常中断了。可以尝试删除 `data/` 目录后重新运行，让程序重新生成合成数据。

**训练不收敛**：如果 loss 一直在一个很高的值不下降，或者 mIoU 始终接近于0，可能是学习率设置不当。尝试将学习率降低10倍（从 1e-4 改为 1e-5），观察是否有改善。另外检查标签数据是否正确——如果标签值全部是0（只有一个类别），模型自然学不到区分不同类别的能力。

**CPU 训练太慢**：如果在 CPU 上训练，建议将 epoch 数降到5-10，batch_size 降到2-4，以快速验证流程是否跑通。正式训练还是需要 GPU。如果你没有本地 GPU，可以考虑使用 Google Colab（免费 GPU）、阿里云 PAI-DSW 或 AutoDL 等云端 GPU 服务。

**rasterio 安装失败**：rasterio 依赖 C++ 编译器和 GDAL 库，在某些环境下安装比较困难。如果你不需要 GeoTIFF 输出功能，可以忽略这个依赖——程序会在启动时打印一条警告并继续运行。如果确实需要安装，推荐使用 conda：`conda install -c conda-forge rasterio`。
