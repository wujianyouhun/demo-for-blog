# 从零开始——手把手教你运行建筑提取训练

这篇文档将引导你一步步完成整个建筑提取项目的部署和运行。无论你是第一次接触深度学习，还是已经有一定经验，这份文档都能帮你顺利跑通整个流程。我们将从环境配置开始，逐步完成数据准备、模型训练、结果可视化和矢量导出的全部环节。

## 环境准备

在开始之前，你需要确保自己的计算机上已经安装了必要的软件和硬件环境。

硬件方面，本项目推荐使用 NVIDIA 显卡进行训练。代码默认针对 RTX 3050 6GB 进行了配置优化，但实际上任何显存大于 4GB 的 NVIDIA 显卡都可以运行本项目。如果你暂时没有独立显卡也不用担心，程序会自动检测到没有 GPU 并切换到 CPU 模式，只是训练速度会明显变慢——在 CPU 上训练 30 个 epoch 可能需要数小时，而在 GPU 上通常只需要十几分钟。

软件方面，你需要安装 Python 3.8 或更高版本，以及以下核心依赖库：

PyTorch 是本项目的深度学习框架基础。推荐使用带有 CUDA 支持的版本，以便利用 GPU 加速训练。你可以通过访问 PyTorch 官网（pytorch.org）选择适合自己系统的安装命令。例如在 Windows 系统上安装 CUDA 11.8 版本，可以执行：

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118
```

NumPy 是科学计算的基础库，负责矩阵运算和数据处理。Pillow（PIL）用于图像文件的读取和格式转换。Matplotlib 用于训练结果和训练曲线的可视化。Rasterio 是可选依赖，仅在需要将预测结果导出为 GeoJSON 矢量数据时才需要安装。

一个完整的环境安装命令如下：

```bash
pip install torch torchvision numpy pillow matplotlib rasterio
```

安装完成后，可以通过以下 Python 代码验证环境是否就绪：

```python
import torch
print(f"PyTorch 版本: {torch.__version__}")
print(f"CUDA 是否可用: {torch.cuda.is_available()}")
if torch.cuda.is_available():
    print(f"GPU 型号: {torch.cuda.get_device_name(0)}")
    vram = torch.cuda.get_device_properties(0).total_mem / 1024**3
    print(f"显存容量: {vram:.1f} GB")
```

如果 PyTorch 版本在 1.10 以上，CUDA 状态显示为 True（前提是你有 NVIDIA 显卡），那么你的环境就已经准备就绪了。

## 数据准备

数据是深度学习的基础。本项目支持两种数据模式：自动生成的合成数据和真实的 WHU Building Dataset。

如果你只是想快速跑通流程、理解项目原理，那么直接使用合成数据即可——程序会在第一次运行时自动生成，无需任何手动操作。合成数据模拟了城市航空影像的基本特征，包括不同形状的建筑（矩形、L 型、十字型）、植被区域、道路和阴影效果，足以支撑模型的学习和验证。

如果你希望使用真实的航空影像数据，需要按照以下目录结构组织你的数据：

```
building-extraction/
├── data/
│   ├── train/
│   │   ├── images/     ← 放置训练用航空影像
│   │   └── labels/     ← 放置对应的建筑二值标签
│   └── val/
│       ├── images/     ← 放置验证用航空影像
│       └── labels/     ← 放置对应的建筑二值标签
```

影像文件支持 `.png`、`.jpg`、`.tif` 和 `.npy` 格式，标签文件支持 `.png`、`.tif` 和 `.npy` 格式。程序会自动匹配影像和标签的配对关系——它们需要具有相同的文件名（仅扩展名可以不同）。

对于标签文件，程序的处理规则是：像素值大于 127 的被视为建筑（标签值为 1），像素值小于等于 127 的被视为非建筑（标签值为 0）。如果你的标签图像是彩色的，程序会自动取第一个通道进行判断。

数据准备的代码逻辑如下，程序会自动检查数据目录并生成合成数据：

```python
# 检查是否存在训练数据
train_img_dir = config.data_dir / "train" / "images"
if not train_img_dir.exists() or len(list(train_img_dir.glob("*"))) == 0:
    print("[INFO] 生成合成建筑数据集...")
    SyntheticBuildingDataset(
        config.data_dir,
        num_train=300, num_val=60,
        img_size=config.img_size
    )
```

合成数据默认生成 300 张训练样本和 60 张验证样本，每张图像大小为 256×256 像素。每张合成影像中会随机放置 3 到 12 个不同形状的建筑物。

## 运行训练

一切准备就绪后，只需要一条命令就可以启动训练：

```bash
python scripts/train.py
```

程序启动后，你会看到一系列的输出信息。首先是欢迎横幅和环境检测信息——程序会告诉你使用的是 GPU 还是 CPU，如果是 GPU 还会显示型号和显存容量。

接下来是数据准备阶段的信息。如果你还没有数据，程序会显示正在生成合成数据的提示，然后逐张生成训练和验证样本。如果数据已经存在，程序会直接加载并显示样本数量。

```
[INFO] 生成 300 张合成建筑样本 (train)...
[INFO] 生成 60 张合成建筑样本 (val)...
[INFO] train 集：300 个样本
[INFO] val 集：60 个样本
```

然后程序会打印模型信息，包括总参数量和注意力门控层数：

```
模型参数量：34,XXX,XXX (XX.X MB)
注意力门控数：4 层
```

紧接着进入正式的训练循环。每个 epoch 结束后，程序会打印详细的训练指标：

```
Epoch 01/30 | Train: 0.8234 | Val: 0.7156 | F1: 0.4523 | IoU: 0.3421 | P: 0.5678 | R: 0.3890 | 12.3s
```

这行信息的含义是：当前是第 1 轮（共 30 轮），训练集平均损失为 0.8234，验证集平均损失为 0.7156，F1 分数为 0.4523，IoU 为 0.3421，Precision 为 0.5678，Recall 为 0.3890，本轮耗时 12.3 秒。

当验证集 F1 分数创出新高时，程序会自动保存当前模型权重，并打印提示信息：

```
  ✓ 保存最优模型 (F1=0.4523)
```

如果连续 8 轮（默认 patience 值）F1 分数都没有提升，程序会触发早停机制，提前结束训练以节省时间。

## 参数配置说明

所有的超参数都集中在 `Config` 类中进行管理，你可以根据自己的硬件条件和需求灵活调整。

```python
class Config:
    # --- 路径 ---
    project_dir = Path(__file__).parent.parent
    data_dir    = project_dir / "data"
    model_dir   = project_dir / "models"
    output_dir  = project_dir / "outputs"

    # --- 数据集 ---
    img_size    = 256          # 裁剪尺寸
    num_classes = 2            # 建筑 / 非建筑（二分类）
    in_channels = 3            # RGB

    # --- 训练 ---
    batch_size  = 4
    epochs      = 30
    lr          = 1e-4
    weight_decay = 1e-4
    patience    = 8

    # --- 数据增强 ---
    use_augmentation = True
```

`img_size` 控制输入图像的尺寸。默认值 256 在大多数 GPU 上都能顺利运行。如果你的显存较大（比如 6GB 以上），可以尝试将其增大到 384 或 512，更大的输入尺寸通常能带来更好的精度，但也会增加显存消耗和训练时间。如果显存不足，可以将其缩小到 192 或 128。

`batch_size` 是每次训练迭代使用的样本数量。默认值 4 适用于 6GB 以上显存的 GPU。如果显存不足导致 Out of Memory 错误，可以将其减小到 2。在 CPU 模式下，建议设为 2 以节省内存。

`epochs` 是最大训练轮数。默认值 30 对合成数据已经足够，在真实数据上可能需要 50 到 100 轮。由于有早停机制，设置稍大的值也不会有问题。

`lr` 是初始学习率。1e-4（即 0.0001）是 Adam 系列优化器常用的起始值。如果你发现训练损失下降过慢，可以尝试增大到 3e-4；如果训练不稳定（损失震荡），可以减小到 5e-5。

`weight_decay` 是权重衰减系数，用于防止过拟合。默认值 1e-4 通常效果良好。

`patience` 控制早停的等待轮数。默认值 8 意味着如果连续 8 轮验证 F1 没有提升就停止训练。在训练初期，模型提升较快，通常不会触发早停。如果你希望训练更充分，可以增大这个值。

`use_augmentation` 控制是否启用数据增强。在训练数据量充足的情况下，开启数据增强可以进一步提升模型的泛化能力。当数据量较少时（比如少于 100 张），数据增强尤为重要。

## 训练输出解读

训练完成后，程序会在 `outputs` 目录下生成多个结果文件，每个文件都有其特定的用途和含义。

`building_extraction_results.png` 是最重要的可视化结果文件，它以四列多行的形式展示了模型在验证集上的预测效果。每行对应一个验证样本，四列分别是：

第一列是原始航空影像，展示模型"看到"的输入内容。第二列是真值建筑标注，用蓝色半透明覆盖在原始影像上，表示人工标注的建筑区域——这是我们希望模型学习到的"正确答案"。第三列是模型预测的建筑区域，用红色半透明覆盖，展示模型"认为"哪里有建筑。第四列是轮廓对比图，将真值边界用蓝色绘制、预测边界用红色绘制在原始影像上，直观地展示两者之间的吻合程度。

![航空影像中的建筑区域分析](http://hellorfimg.zcool.cn/large/2255300517.jpg)

理想情况下，第三列（红色预测）应该与第二列（蓝色真值）高度一致。第四列中蓝色和红色的边界应该几乎重合——如果两者之间存在明显的间距或错位，说明模型的边界精度还有提升空间。

`training_curves.png` 包含两个子图。左侧的损失曲线展示了训练损失和验证损失随 epoch 的变化趋势——理想情况下两条曲线都应该稳步下降，且验证损失不应明显高于训练损失（否则可能存在过拟合）。右侧的 F1 精度曲线展示了验证集 F1 分数随 epoch 的变化——理想情况下这条曲线应该稳步上升并逐渐趋于平稳。

`best_attention_unet.pth` 保存在 `models` 目录下，是验证集上表现最好的模型权重文件。你可以用它来进行后续的推理、部署或迁移学习。

`buildings.geojson` 是建筑矢量数据文件（需要安装 rasterio），它将模型预测的建筑栅格转换为 GeoJSON 多边形格式，可以直接导入 QGIS、ArcGIS 等 GIS 软件进行空间分析。

## GeoJSON 矢量导出功能说明

在实际应用中，仅仅得到像素级的预测掩膜往往不够——我们通常需要矢量化建筑轮廓，才能在 GIS 系统中进行面积计算、空间查询、属性关联等操作。

本项目的 `export_building_vector` 函数实现了从栅格预测到矢量导出的完整流程：

```python
# 使用 rasterio 从栅格预测中提取多边形
for geom, value in features.shapes(pred, transform=transform):
    if value == 1:  # 建筑
        all_polygons.append({
            "type": "Feature",
            "geometry": geom,
            "properties": {"class": "building", "source": f"sample_{i}"}
        })
```

这个函数的工作流程分为三步。首先，对验证样本进行模型推理，获得二值预测结果。其次，使用 rasterio 的 `features.shapes` 函数将连通的建筑像素区域转换为多边形几何对象。最后，将所有多边形组装为标准的 GeoJSON FeatureCollection 格式，并保存为 `.geojson` 文件。

![GIS 中的建筑矢量数据可视化](http://q6.itc.cn/images01/20240301/ea54005c96d04d02b4f20263396d6f7a.png)

需要注意的是，当前演示代码使用的是模拟的地理坐标变换（以西安附近的经纬度为例），在实际应用中你需要替换为与航空影像匹配的真实地理坐标信息。GeoJSON 文件可以直接在 QGIS 中打开查看，也可以导入到 PostgreSQL/PostGIS 数据库中进行空间查询和分析。

## 常见问题排查

**问题：运行时出现 "CUDA out of memory" 错误。** 这是显存不足导致的。解决方法是在 `Config` 类中减小 `batch_size`（比如从 4 改为 2），或者减小 `img_size`（比如从 256 改为 192）。

**问题：程序提示 "在 data/train/images 中未找到数据"。** 这说明数据目录不存在或目录为空。如果你希望使用合成数据，请确保 data 目录下没有任何残留的空文件夹——删除整个 data 目录后重新运行程序，它会自动生成合成数据。如果你希望使用自己的数据，请确保影像和标签文件已正确放置在对应的目录中。

**问题：训练过程中损失值出现 NaN。** 这通常是学习率过大或数据异常导致的。首先尝试将学习率从 1e-4 减小到 5e-5，其次检查输入数据是否都经过了正确的归一化（像素值应在 0 到 1 之间）。

**问题：验证 F1 分数始终很低。** 可能的原因包括：训练数据量太少（合成数据默认 300 张，可以尝试增加到 1000 张以上），模型训练不充分（增大 epochs 值），或者数据增强过于激进。你可以先关闭数据增强（`use_augmentation = False`），看基础性能是否提升。

**问题：GeoJSON 文件未生成。** 需要确保已安装 rasterio 库。在某些系统上，rasterio 的安装可能比较复杂（需要 GDAL 依赖），可以参考 rasterio 官方文档进行安装。如果 rasterio 未安装，程序会跳过矢量导出步骤，不影响其他功能的正常运行。

## 如何用自己的航空影像数据

如果你手头有自己的航空影像数据，可以按照以下步骤将其适配到本项目中。

首先，准备影像和标签的配对文件。影像应为 RGB 三通道的彩色图像，标签应为与影像等大的单通道图像，其中建筑区域为白色（像素值 255），非建筑区域为黑色（像素值 0）。

其次，将影像裁剪为统一尺寸。如果你的原始影像尺寸很大（比如 5000×5000 像素的航空正射图），需要先将其裁剪为固定大小的小块（tiles）。推荐使用 256×256 或 512×512 的尺寸，裁剪时注意保持影像和标签的空间对齐，裁剪块之间可以有适当的重叠（overlap）以减少边界效应。

然后，将裁剪好的影像和标签分别放入 `data/train/images/`、`data/train/labels/`、`data/val/images/`、`data/val/labels/` 目录中。建议按照 80:20 的比例划分训练集和验证集。

最后，确保影像文件名的对应关系。比如 `image_001.png` 对应的标签应该是 `image_001.png`（或 `image_001.tif`、`image_001.npy`）。程序会自动根据文件名进行配对。

完成以上准备后，直接运行 `python scripts/train.py` 即可开始训练，其余流程与合成数据完全一致。训练完成后，你可以在可视化结果中直观地看到模型在你的数据上的表现，并根据需要进一步调优参数或增加训练数据量。
