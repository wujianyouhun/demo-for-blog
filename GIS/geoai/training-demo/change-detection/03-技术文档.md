# 孪生U-Net——变化检测的技术核心

在前两篇文档中，你已经了解了变化检测的基本概念，也成功运行了训练流程。现在，让我们深入到代码的最核心部分，逐层剖析孪生U-Net的架构设计和实现原理。这篇文档的目标是让你不仅会"用"这个模型，更能真正"理解"它为什么这样设计、每一层在做什么、为什么这样做能检测出变化。

## 孪生网络架构的设计哲学

孪生网络（Siamese Network）的名字来自希腊神话中的双胞胎。它的核心思想很简单但很深刻：使用两个结构完全相同、权重完全共享的子网络分别处理两个输入，然后比较它们的输出来判断差异。

为什么两个输入要共享编码器？这是理解孪生网络的关键。让我们用一个类比来解释：假设你有两个翻译员，一个负责翻译2010年的中文文章，一个负责翻译2020年的中文文章。如果这两个翻译员的翻译水平、风格、标准完全不同，那么即使原文的内容一样，翻译出来的英文也可能差异很大——这不是因为原文变了，而是因为翻译方式不同。但如果两个翻译员是同一个人（共享权重），那翻译出来的差异就只可能来自原文本身的差异。

在变化检测中，编码器就是这个"翻译员"——它把原始图像"翻译"成特征表示。共享编码器确保了"同样的地物产生同样的特征"，这样当特征出现差异时，我们就有充分的理由认为这是地表发生了真实变化，而不是编码方式造成的假象。

![编码器-解码器架构示意](http://pic1.zhimg.com/v2-0187af3808d630d840fc116e945368c4_r.jpg)

从代码层面来看，孪生结构体现在SiamUNet的forward方法中——同一个self.encoder被调用了两次，分别处理img_a和img_b：

```python
def forward(self, img_a, img_b):
    feats_a = self.encoder(img_a)
    feats_b = self.encoder(img_b)
    output = self.decoder(feats_a, feats_b)
    return output
```

注意这里的`self.encoder`是同一个对象，不是两个独立的编码器。在PyTorch中，这意味着两次调用使用的是完全相同的权重参数。这就是"共享权重"在代码中的体现——不是两个长得一样的编码器，而是同一个编码器被调用了两次。

## Encoder类：多层特征提取

Encoder类是整个模型的"眼睛"，负责从原始图像中提取有信息量的特征。它的设计灵感来自经典的VGG网络和U-Net编码器，采用了逐步下采样、逐步增加通道数的策略。

```python
class Encoder(nn.Module):
    """
    共享编码器（孪生结构的核心）

    两个时相的图像通过同一个编码器提取特征。
    共享权重意味着模型对"相同内容在不同时间拍摄"有一致的理解。
    """

    def __init__(self, in_channels=3):
        super().__init__()
        self.enc1 = ConvBlock(in_channels, 64)
        self.pool1 = nn.MaxPool2d(2)
        self.enc2 = ConvBlock(64, 128)
        self.pool2 = nn.MaxPool2d(2)
        self.enc3 = ConvBlock(128, 256)
        self.pool3 = nn.MaxPool2d(2)
        self.enc4 = ConvBlock(256, 512)
        self.pool4 = nn.MaxPool2d(2)

    def forward(self, x):
        """返回各层特征用于跳跃连接"""
        e1 = self.enc1(x)                # (B, 64, H, W)
        e2 = self.enc2(self.pool1(e1))   # (B, 128, H/2, W/2)
        e3 = self.enc3(self.pool2(e2))   # (B, 256, H/4, W/4)
        e4 = self.enc4(self.pool3(e3))   # (B, 512, H/8, W/8)
        b = self.pool4(e4)               # (B, 512, H/16, W/16)
        return e1, e2, e3, e4, b
```

这个编码器有四层卷积块（ConvBlock），每层之后都有一个2×2的最大池化操作，将特征图的空间尺寸减半。通道数的变化规律是3→64→128→256→512，每一层翻倍。这种设计的逻辑是：随着空间分辨率的降低，我们需要更多的通道来承载更复杂的语义信息。

第一层（enc1）处理原始RGB图像，提取的是低层次的视觉特征——边缘、颜色梯度、简单纹理。在变化检测的语境下，这一层能捕捉到像素级别的颜色和亮度差异，比如新建建筑与周围空地的色彩对比。

第二层（enc2）在第一层的基础上提取更复杂的模式——角点、局部结构、简单形状。经过一次池化后，空间分辨率降为原来的一半，这意味着这一层的每个特征像素"看到"的是原始图像中2×2的区域。

第三层（enc3）开始提取语义级别的特征——建筑轮廓、道路走向、植被区域的边界。空间分辨率降为原来的四分之一，每个特征像素对应原始图像中4×4的区域。

第四层（enc4）提取最高级的语义特征——整个建筑的完整表示、区域的土地利用类型。空间分辨率降为原来的八分之一，每个特征像素覆盖8×8的区域。

最后的bottleneck（瓶颈层）通过第四次池化将特征图压缩到原始尺寸的十六分之一。这个最小尺寸的特征图包含了最浓缩的全局信息。

对于256×256的输入图像，各层特征图的尺寸分别是：e1为256×256（64通道），e2为128×128（128通道），e3为64×64（256通道），e4为32×32（512通道），b为16×16（512通道）。

编码器最重要的设计决策是返回所有中间层的特征（e1到e4），而不仅仅是最终的bottleneck特征。这是因为不同尺度的特征对变化检测有不同的贡献：低层特征（e1、e2）保留了精细的空间细节，有助于定位变化的精确边界；高层特征（e3、e4、b）包含丰富的语义信息，有助于判断"这种差异是否代表真正的地表变化"。

## ConvBlock：基础卷积单元

ConvBlock是编码器中反复使用的基础模块，它由两个卷积层组成，每个卷积层后面都跟着批归一化（BatchNorm）和ReLU激活函数。

```python
class ConvBlock(nn.Module):
    """双卷积块"""
    def __init__(self, in_ch, out_ch):
        super().__init__()
        self.conv = nn.Sequential(
            nn.Conv2d(in_ch, out_ch, 3, padding=1, bias=False),
            nn.BatchNorm2d(out_ch),
            nn.ReLU(inplace=True),
            nn.Conv2d(out_ch, out_ch, 3, padding=1, bias=False),
            nn.BatchNorm2d(out_ch),
            nn.ReLU(inplace=True),
        )

    def forward(self, x):
        return self.conv(x)
```

这个设计直接继承自U-Net的原始论文。使用两个3×3卷积而不是一个5×5卷积，有两个好处：一是参数量更少（两个3×3卷积的参数是2×9=18，而一个5×5卷积是25）；二是经过两层非线性变换，模型的表达能力更强。padding设为1确保输出尺寸与输入相同，bias设为False是因为后面的BatchNorm会抵消偏置的效果。

BatchNorm（批归一化）的作用是将每个通道的特征归一化到均值为0、方差为1的分布，然后通过学习两个参数（缩放和平移）来恢复表达能力。这看起来多此一举，但实际上它极大地稳定了训练过程——使得模型对学习率的选择不再那么敏感，同时起到轻微的正则化效果。

## 差异融合机制：变化检测的灵魂

如果说共享编码器是孪生网络的"眼睛"，那差异融合就是它的"大脑"——它负责从两个时相的特征中识别出变化的信号。

本项目的差异融合采用了绝对差值的方式：对于编码器的每一层特征，计算时相B和时相A特征的绝对差 |B - A|。让我们从直觉和数学两个角度来理解这个操作。

从直觉上看，绝对差值的含义非常清晰：如果某个位置在两个时相中的特征完全相同（地表没变），差值就是0；如果特征发生了显著变化（地表发生了改变），差值就会很大。使用绝对值而不是简单差值（B - A），是因为变化是"无方向"的——新建一栋建筑和拆除一栋建筑都是变化，不应该因为方向不同而被抵消。简单差值可能会让"新增"和"消失"的变化互相抵消，而绝对差值确保了所有变化都被同等对待。

从数学角度看，绝对差值操作可以表示为：

```
D_l = |f_l(B) - f_l(A)|
```

其中f_l是编码器第l层的特征提取函数，D_l是该层的差异特征图。这个差异特征图的空间分辨率与编码器特征相同，通道数也相同。每个通道可以理解为一种特定的"变化特征"——有些通道可能对建筑变化敏感，有些可能对颜色变化敏感。

在ChangeDecoder的实现中，差异融合不仅使用了差值特征，还拼接了时相B的原始特征：

```python
def forward(self, feats_a, feats_b):
    e1_a, e2_a, e3_a, e4_a, b_a = feats_a
    e1_b, e2_b, e3_b, e4_b, b_b = feats_b

    # 差异融合：|B - A| + 拼接
    diff_b = torch.abs(b_b - b_a)
    x = torch.cat([diff_b, b_b], dim=1)  # (B, 1024, H/16, W/16)
    x = self.dec4(x)                      # (B, 256, H/16, W/16)
```

为什么还要拼接原始特征？因为仅有差异信息是不够的。考虑这样一个场景：两个时相中都有一栋建筑，但B中建筑的颜色因光照不同而略深。这会产生一个非零的差异信号，但它不是真实的地表变化。如果解码器只看到差异信号，可能会把这种光照差异误判为变化。但如果解码器同时看到原始特征，它就能结合"这个区域在两幅图中都是建筑"的上下文信息，正确地判断这不是真实变化。

## ChangeDecoder：逐层上采样与跳跃连接

ChangeDecoder的任务是将从差异融合得到的特征逐步恢复到原始图像的尺寸，并在过程中不断细化变化区域的边界。

```python
class ChangeDecoder(nn.Module):
    def __init__(self, num_classes=2):
        super().__init__()
        self.up4 = nn.Upsample(scale_factor=2, mode="bilinear", align_corners=True)
        self.up3 = nn.Upsample(scale_factor=2, mode="bilinear", align_corners=True)
        self.up2 = nn.Upsample(scale_factor=2, mode="bilinear", align_corners=True)
        self.up1 = nn.Upsample(scale_factor=2, mode="bilinear", align_corners=True)

        self.dec4 = ConvBlock(512 + 512, 256)
        self.dec3 = ConvBlock(256 + 512, 128)
        self.dec2 = ConvBlock(128 + 256, 64)
        self.dec1 = ConvBlock(64 + 128, 32)

        self.final = nn.Conv2d(32, num_classes, kernel_size=1)
```

解码器的结构像是一个倒过来的编码器，有四个上采样步骤，每个步骤将特征图的空间尺寸翻倍。在每个步骤中，解码器会接收来自编码器的跳跃连接——对应层的差异特征。

上采样使用双线性插值（bilinear interpolation），它比转置卷积（transposed convolution）更稳定，不容易产生棋盘格伪影。scale_factor=2意味着每次上采样将尺寸翻倍：16×16 → 32×32 → 64×64 → 128×128 → 256×256。

跳跃连接是U-Net架构最精妙的设计之一。在编码器中，随着层层下采样，空间细节信息不可避免地丢失了。跳跃连接通过"短路"的方式，将编码器中高分辨率的特征直接传递给解码器的对应层，让解码器在恢复空间尺寸的同时获得精细的位置信息。

在变化检测的场景中，跳跃连接传递的是差异特征。让我们追踪一个具体的解码步骤：

```python
    # 第一层解码：bottleneck差异 + 时相B特征
    diff_b = torch.abs(b_b - b_a)
    x = torch.cat([diff_b, b_b], dim=1)  # 512+512=1024通道
    x = self.dec4(x)                      # 1024→256通道

    # 第二层解码：上采样 + enc4层的差异
    x = self.up4(x)                       # 16×16 → 32×32
    diff_4 = torch.abs(e4_b - e4_a)       # enc4层的差异特征
    x = torch.cat([x, diff_4], dim=1)     # 拼接
    x = self.dec3(x)                      # 256+512→128通道
```

在第二层解码中，来自上一层的特征（经过上采样后为32×32、256通道）与编码器第四层的差异特征（32×32、512通道）拼接，形成32×32、768通道的特征图。然后经过一个ConvBlock将通道数压缩到128。这样，解码器在32×32这个尺度上，同时拥有了来自bottleneck的全局变化信息和来自enc4层的局部变化细节。

这种多尺度差异融合的方式确保了模型既不会遗漏大范围的宏观变化（来自bottleneck的全局信息），也不会忽略小面积的精细变化（来自低层的高分辨率信息）。

最终的分类层使用1×1卷积，将32通道的特征图映射为2通道的概率图——每个像素有两个值，分别代表"未变化"和"变化"的概率。取概率较大的类别作为最终预测结果。

## SiamUNet完整前向传播流程

让我们完整追踪一次数据从输入到输出的流动过程，将所有模块串联起来。假设输入的图像尺寸为256×256×3，批大小为3。

输入阶段：两张图像img_a和img_b，尺寸都是(3, 3, 256, 256)。

编码阶段（共享编码器处理img_a）：
- enc1: 3→64通道，输出e1_a尺寸(3, 64, 256, 256)
- pool1→enc2: 64→128通道，输出e2_a尺寸(3, 128, 128, 128)
- pool2→enc3: 128→256通道，输出e3_a尺寸(3, 256, 64, 64)
- pool3→enc4: 256→512通道，输出e4_a尺寸(3, 512, 32, 32)
- pool4: 输出b_a尺寸(3, 512, 16, 16)

编码阶段（同一个编码器处理img_b）：产生e1_b到b_b，尺寸完全对应。

解码阶段（差异融合与上采样）：
- 计算bottleneck差异：|b_b - b_a|，拼接b_b，ConvBlock压缩到256通道
- 上采样到32×32，拼接enc4差异，ConvBlock压缩到128通道
- 上采样到64×64，拼接enc3差异，ConvBlock压缩到64通道
- 上采样到128×128，拼接enc2差异，ConvBlock压缩到32通道
- 上采样到256×256

分类阶段：1×1卷积将32通道映射为2通道，输出尺寸(3, 2, 256, 256)。

整个前向传播过程中，最关键的是每个尺度上的差异特征计算。模型在四个不同的空间尺度上检测变化：256×256（像素级细节）、128×128（局部结构）、64×64（建筑轮廓）、32×32（区域语义）和16×16（全局上下文）。这种多尺度检测能力使得模型既能发现小面积的建筑增减，也能识别大范围的土地利用变化。

## ChangeLoss：应对类别不平衡

变化检测面临的最大挑战之一是类别极度不平衡——通常只有5%到20%的像素是"变化"的。如果使用普通的交叉熵损失，模型很容易学到一种"偷懒"策略：把所有像素都预测为"未变化"，就能获得很高的准确率，但完全检测不出变化区域。

本项目采用了加权交叉熵和Focal Loss的组合来解决这个问题。

```python
class ChangeLoss(nn.Module):
    """
    变化检测专用损失函数：加权交叉熵 + Focal Loss

    变化检测的核心挑战是类别极度不平衡——
    通常只有 5%~20% 的像素是"变化"的。
    """

    def __init__(self, pos_weight=5.0):
        super().__init__()
        self.ce = nn.CrossEntropyLoss(
            weight=torch.tensor([1.0, pos_weight])
        )
        self.gamma = 2.0

    def forward(self, pred, target):
        ce_loss = self.ce(pred, target)

        # Focal Loss
        pred_prob = F.softmax(pred, dim=1)
        target_onehot = F.one_hot(target, 2).permute(0, 3, 1, 2).float()
        focal_weight = (1 - pred_prob) ** self.gamma
        focal_loss = -(focal_weight * target_onehot * torch.log(pred_prob + 1e-8)).mean()

        return ce_loss + focal_loss * 0.5
```

加权交叉熵的思路很直接：给"变化"类别一个更高的权重（默认5.0），使得误判一个变化像素的代价是误判一个未变化像素的5倍。这就迫使模型更加重视变化区域的检测——即使变化像素少，它们对总损失的贡献也被放大了。

Focal Loss是2017年由何恺明等人在RetinaNet论文中提出的损失函数，专门用于解决类别不平衡问题。它的核心思想是：对于模型已经能正确分类的"简单样本"，降低它们的损失权重；把更多的训练信号集中在那些"难以分类"的样本上。

![Focal Loss原理示意](http://www.jeremyjordan.me/content/images/2018/07/Screen-Shot-2018-07-10-at-10.34.22-PM.png)

数学上，Focal Loss在交叉熵的基础上增加了一个调制因子(1-p)^gamma。当一个样本被正确分类时（p接近1），这个因子接近0，意味着它对总损失的贡献很小；当一个样本被错误分类时（p接近0），这个因子接近1，保持了完整的损失贡献。gamma=2是常用的默认值，它使得容易样本的权重衰减得更快。

在变化检测的场景下，Focal Loss的效果是这样的：大量的"未变化"像素通常很容易被正确分类（模型很快就学会了"大多数地方不会变"），所以Focal Loss会自动降低它们的权重。而那些变化区域——尤其是变化的边界、小面积的变化——往往是难以正确分类的，Focal Loss会让模型把更多的注意力集中在这些困难样本上。

最终的损失是加权交叉熵和Focal Loss的加权和：ce_loss + 0.5 * focal_loss。系数0.5是一个经验值，确保两种损失在数值上大致平衡，不会让某一种主导训练过程。

## 评价指标的深入理解

compute_change_metrics函数计算了五个评价指标，每个指标从不同的角度衡量模型的性能。

```python
def compute_change_metrics(pred, target, num_classes=2):
    pred_binary = pred.argmax(dim=1)

    tp = ((pred_binary == 1) & (target == 1)).sum().float()
    fp = ((pred_binary == 1) & (target == 0)).sum().float()
    fn = ((pred_binary == 0) & (target == 1)).sum().float()
    tn = ((pred_binary == 0) & (target == 0)).sum().float()

    precision = tp / (tp + fp + 1e-8)
    recall = tp / (tp + fn + 1e-8)
    f1 = 2 * precision * recall / (precision + recall + 1e-8)
    iou = tp / (tp + fp + fn + 1e-8)
    oa = (tp + tn) / (tp + fp + fn + tn + 1e-8)

    return {
        "F1": f1.item(), "IoU": iou.item(), "OA": oa.item(),
        "Precision": precision.item(), "Recall": recall.item(),
    }
```

这四个基础统计量构成了所有指标的基石。TP（True Positive）是模型正确检测到的变化像素；FP（False Positive）是模型误报的变化像素（实际没变但预测变了）；FN（False Negative）是模型漏检的变化像素（实际变了但预测没变）；TN（True Negative）是模型正确识别的未变化像素。

Precision（精确率）= TP / (TP + FP)：在模型预测为"变化"的所有像素中，真正变化的比例。高精确率意味着模型很少误报——当它说"这里变了"，大概率真的变了。

Recall（召回率）= TP / (TP + FN)：在所有真正变化的像素中，模型检测到的比例。高召回率意味着模型很少漏检——大部分真实的变化都被找到了。

F1 = 2 × Precision × Recall / (Precision + Recall)：精确率和召回率的调和平均值。调和平均的特点是它对极端值很敏感——如果精确率很高但召回率很低（或反过来），F1会被拉到较低的值。只有当两者都高时，F1才会高。这确保了模型不会通过牺牲一方面来提升另一方面。

IoU = TP / (TP + FP + FN)：预测变化区域和真实变化区域的交并比。它衡量的是两个区域的空间重叠程度。IoU和F1之间有严格的数学关系：IoU = F1 / (2 - F1)，所以IoU总是小于等于F1。

OA = (TP + TN) / (TP + FP + FN + TN)：总体精度，所有正确预测占总像素的比例。如前所述，这个指标在类别不平衡时容易误导。

代码中的1e-8是一个很小的常数，加在分母上防止除零错误。当某个分母恰好为0时（比如没有变化像素导致TP+FP=0），这个常数确保计算不会崩溃。

## 数据增强的同步性要求

数据增强是深度学习中常用的技术，通过对训练图像做随机变换来增加数据的多样性，防止模型过拟合。在变化检测中，数据增强有一个非常重要的约束：对时相A、时相B和标签图必须做完全相同的几何变换。

```python
def _augment(self, img_a, img_b, label):
    """同步增强：对 A、B、标签做相同的几何变换"""
    if random.random() > 0.5:
        img_a = np.flip(img_a, axis=1).copy()
        img_b = np.flip(img_b, axis=1).copy()
        label = np.flip(label, axis=0).copy()

    if random.random() > 0.5:
        img_a = np.flip(img_a, axis=0).copy()
        img_b = np.flip(img_b, axis=0).copy()
        label = np.flip(label, axis=1).copy()

    k = random.randint(0, 3)
    if k > 0:
        img_a = np.rot90(img_a, k, axes=(0, 1)).copy()
        img_b = np.rot90(img_b, k, axes=(0, 1)).copy()
        label = np.rot90(label, k, axes=(0, 1)).copy()
```

为什么必须同步？因为变化检测依赖的是A和B之间的空间对应关系。如果A被水平翻转了但B没有，那么同一个地物在A和B中的位置就错位了，模型会看到大量"虚假变化"。同样，如果标签图没有做对应的变换，变化区域的位置就和实际图像对不上了。

代码实现了三种几何变换：水平翻转（50%概率）、垂直翻转（50%概率）、随机旋转0到270度。每种变换都同时对A、B和label执行，确保三者的空间关系始终一致。

值得注意的是颜色抖动的处理方式。代码中对A和B做了独立的亮度调整：

```python
    # 独立颜色抖动（A、B 各自独立，模拟不同拍摄条件）
    for img in [img_a, img_b]:
        if random.random() > 0.5:
            brightness = random.uniform(0.9, 1.1)
            img[:] = np.clip(img * brightness, 0, 1)
```

这里故意对A和B做不同的亮度调整，目的是模拟真实场景中两个时相的拍摄条件差异——不同时间拍摄的光照角度、天气条件、大气状况都可能不同，导致同一地物在两幅图像中的亮度和颜色有差异。通过这种独立的颜色抖动，模型被迫学习区分"光照差异造成的表观变化"和"地表真实变化"，从而提升对伪变化的鲁棒性。

几何变换必须同步，颜色变换可以独立——这是变化检测数据增强的一条重要原则。
