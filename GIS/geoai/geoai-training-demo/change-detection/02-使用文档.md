# 从零开始——手把手教你运行变化检测训练

读完第一篇项目说明后，你已经对变化检测有了一个整体的认识。现在，让我们卷起袖子，从零开始把这个项目跑起来。这篇文档将带你走过每一个步骤，从环境准备到训练完成，确保你能顺利完成第一次变化检测实验。

## 环境准备

在开始之前，你需要确保自己的计算环境满足以下基本要求。变化检测是一个计算密集型的任务，特别是在使用深度学习模型时，GPU加速几乎是必需的。

硬件方面，你需要一块至少拥有6GB显存的NVIDIA显卡。本项目的默认配置是针对RTX 3060（12GB显存）设计的。如果你的显卡显存更小（比如4GB的GTX 1650），你需要相应减小batch_size参数。如果你没有独立显卡也不用灰心，项目代码支持CPU模式，只是训练速度会慢很多——一个epoch可能需要十几分钟而不是几十秒。

软件方面，你需要Python 3.8或更高版本，以及以下核心依赖库：

```bash
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu118
pip install numpy pillow matplotlib
```

PyTorch的安装命令中`cu118`表示CUDA 11.8版本，你需要根据自己显卡驱动的CUDA版本选择合适的安装命令。可以在NVIDIA控制面板或终端中运行`nvidia-smi`来查看你的CUDA版本。如果你使用CPU，可以省略CUDA后缀。

NumPy是数值计算的基础库，PIL（Pillow）用于图像处理，Matplotlib用于可视化。这三个库都会在训练过程中被使用到。项目代码中做了容错处理——如果Matplotlib未安装，可视化步骤会被自动跳过，不影响训练本身。

## 项目目录结构

把项目代码下载后，你会看到这样的目录结构：

```
change-detection/
├── scripts/
│   └── train.py          ← 主训练脚本（所有代码都在这一个文件中）
├── data/                  ← 数据目录（运行后自动生成）
│   ├── train/
│   │   ├── A/            ← 时相A训练图像
│   │   ├── B/            ← 时相B训练图像
│   │   └── label/        ← 变化标签
│   └── val/
│       ├── A/
│       ├── B/
│       └── label/
├── models/                ← 模型权重（训练后生成）
└── outputs/               ← 可视化输出（训练后生成）
```

这种A/B/label三目录的组织方式是变化检测领域最标准的数据组织格式。LEVIR-CD数据集、WHU-CD数据集、DSIFN-CD数据集等都采用这种结构。当你将来使用真实数据集时，只需要把对应的影像文件放到这三个目录中即可。

## 数据组织方式详解

理解数据组织方式是理解变化检测的第一步。让我们详细看看每个目录里放的是什么。

A目录存放的是"时相A"的影像——也就是较早时间拍摄的图像。在我们的合成数据中，这些是模拟的城市场景图像，包含了建筑、道路、植被等元素。每张图像的尺寸为256×256像素，3个通道（RGB），数据类型为float32，像素值范围在0到1之间。

B目录存放的是"时相B"的影像——也就是较晚时间拍摄的同一地点的图像。在合成数据中，B是在A的基础上，随机在若干区域做了变化（新建建筑或拆除建筑）后得到的。A和B的图像必须精确对齐——同一个像素位置对应地面上的同一个地点。

label目录存放的是变化标签图。每张标签图是一个二维矩阵，尺寸为256×256，数据类型为int64，值为0（未变化）或1（变化）。标签图与A、B图像的空间对应关系必须精确：如果标签图中坐标(x, y)的值为1，就意味着从时相A到时相B，地面坐标(x, y)处的地表覆盖发生了改变。

这种三目录结构的一个重要特点是文件名必须匹配。代码通过文件名来配对A、B和label。比如A目录中的`pair_0001.npy`，必须对应B目录中的`pair_0001.npy`和label目录中的`pair_0001.npy`。代码会自动搜索.npy、.png和.tif三种格式的文件，但同一组数据需要保持格式一致。

## 运行训练

一切准备就绪后，运行训练只需要一条命令：

```bash
python scripts/train.py
```

就这么简单！脚本会自动完成以下所有步骤。

第一步是数据准备。脚本会检查data/train/A目录中是否已有数据。如果没有（首次运行），它会自动调用合成数据生成器，创建200对训练样本和50对验证样本。你会在控制台看到类似这样的输出：

```
[INFO] 生成 200 对合成变化检测样本 (train)...
[INFO] 生成 50 对合成变化检测样本 (val)...
```

每对样本包含三个文件：A图像、B图像和label标签。生成过程大约需要十几秒，之后数据会被保存到对应的目录中。如果你再次运行脚本，它会检测到已有数据并跳过生成步骤。

第二步是构建孪生U-Net模型。脚本会实例化SiamUNet类，并打印模型的参数信息。你会看到模型总参数量和各模块的参数分布：

```
模型参数量：XX,XXX,XXX (XX.X MB)
编码器参数（共享）：XX,XXX,XXX
解码器参数：XX,XXX,XXX
```

第三步是模型训练。这是整个流程中耗时最长的部分。每个epoch，模型会遍历所有训练样本，进行前向传播、计算损失、反向传播和参数更新。然后会在验证集上评估模型性能，计算F1、IoU和OA三个指标。你会看到每个epoch的进度输出：

```
Epoch 01/30 | Train: 0.8234 | Val: 0.7156 | F1: 0.6532 | IoU: 0.4851 | OA: 0.9123 | LR: 0.000100 | 12.3s
Epoch 02/30 | Train: 0.6543 | Val: 0.6234 | F1: 0.7102 | IoU: 0.5506 | OA: 0.9245 | LR: 0.000099 | 12.1s
```

训练过程中有两个重要的自动化机制。首先是学习率调度——使用余弦退火策略，从初始学习率逐渐降低到初始值的1%。这种策略的好处是让模型在训练初期快速学习，在训练后期精细调优。其次是早停（Early Stopping）机制——如果连续8个epoch验证集F1分数都没有提升，训练会自动终止。这可以防止模型过拟合，同时节省训练时间。

第四步是模型评估。训练结束后，脚本会加载验证过程中表现最好的那个模型权重（而不是最后一个epoch的权重），在验证集上做最终的全面评估。

第五步是可视化。脚本会生成两种可视化结果：变化检测结果图和训练曲线图。

## 参数调整指南

Config类集中管理了所有可调参数。对于初学者，以下几个参数最值得关注和调整。

batch_size（批大小）是变化检测项目中最需要注意的参数。与普通语义分割不同，孪生网络每个训练样本需要同时加载两张图像（时相A和时相B），这意味着显存消耗大约是普通分割任务的两倍。默认的batch_size为6，适合12GB显存的GPU。如果你的显存只有8GB，建议将batch_size降低到4；如果只有6GB，可以降到2或3。如果遇到显存不足的错误（CUDA Out of Memory），首先尝试减小batch_size。

```python
class Config:
    batch_size  = 6            # 孪生网络需要双倍显存，适当减小 batch
    epochs      = 30
    lr          = 1e-4
    weight_decay = 1e-4
    patience    = 8
```

epochs（训练轮数）设为30是一个比较保守的值。对于合成数据，通常15到20个epoch就能收敛。对于真实的LEVIR-CD数据集，可能需要50到100个epoch。早停机制会自动在合适的时机停止训练，所以设得稍大一些也没有问题。

lr（学习率）设为0.0001是一个相对保守的值，适合大多数情况。如果你发现训练损失下降非常缓慢，可以尝试增大到0.0003；如果训练不稳定（损失震荡），可以减小到0.00005。

patience（早停耐心值）设为8，意味着连续8个epoch没有提升就停止训练。合成数据的训练中，模型通常在10到15个epoch后就能接近最优性能。

img_size（图像裁剪尺寸）设为256。这个尺寸是一个权衡——越大，模型能看到的上下文越多，但显存消耗也越大。对于256×256的输入，编码器会将图像逐步下采样到16×16的特征图，这对于捕捉建筑级别的变化已经足够。

## 训练输出解读

训练过程中打印的指标是评估模型性能的关键。让我们逐一理解这些指标的含义。

F1 Score是变化检测最重要的指标。它是精确率（Precision）和召回率（Recall）的调和平均值。精确率衡量的是"模型预测为变化的像素中，有多少确实发生了变化"——也就是预测的准确性。召回率衡量的是"所有真正发生变化的像素中，有多少被模型检测到了"——也就是检测的全面性。F1综合了这两个方面，取值在0到1之间，越高越好。在合成数据上，一个好的模型可以达到0.85以上的F1；在真实的LEVIR-CD数据集上，0.70以上的F1就算不错的结果了。

IoU（Intersection over Union，交并比）是另一个核心指标。它计算的是"预测的变化区域和真实的变化区域的交集面积"除以"它们的并集面积"。直觉上说，IoU衡量的是预测的变化区域和真实变化区域的重合程度。IoU总是小于等于F1——如果你看到F1很高但IoU明显偏低，说明模型虽然大体找到了变化区域，但边界定位不够精确。

OA（Overall Accuracy，总体精度）是最直观但也最容易误导人的指标。它计算的是"所有正确预测的像素"占"所有像素"的比例。问题在于，由于变化检测中"未变化"像素占绝大多数（80%以上），即使模型把所有像素都预测为"未变化"，OA也能达到80%以上。所以千万不要被高OA值所迷惑——一定要结合F1和IoU来综合评估。

一个典型的训练过程是这样的：前几个epoch，损失快速下降，F1快速上升；到中间阶段，下降和上升的速度放缓；最后几个epoch，指标趋于平稳。如果你画出的训练曲线呈现这种形态，说明训练是健康的。如果训练损失持续下降但验证损失在某个点后开始上升，那就是过拟合的信号——模型开始"记住"训练数据的特征，而不是学习通用的变化检测能力。

## 可视化结果解读

训练完成后，脚本会生成一个变化检测结果的可视化图。这个图包含五列子图，每行代表一个验证样本。

第一列是时相A——较早时间拍摄的图像。这是变化的"起点"，你可以看到当时的城市面貌：建筑物、道路、植被等。

第二列是时相B——较晚时间拍摄的图像。仔细对比A和B，你应该能发现一些差异——某些区域多了新的建筑，或者某些建筑消失了变成了空地。

第三列是真值变化图。绿色代表"未变化"区域，红色代表"变化"区域。这是人工标注的标准答案，用来和模型预测做对比。

第四列是模型预测的变化图。同样用绿色表示"未变化"，红色表示"变化"。把这一列和第三列做对比，就能直观地看到模型检测的准确程度。理想的预测应该和真值高度吻合——红色区域的位置和形状都基本一致。

第五列是变化叠加图。模型的预测结果（红色高亮）叠加到了时相B的图像上。这种可视化方式非常直观——你可以直接看到模型检测到的变化区域在真实图像中的位置，便于理解变化的实际含义。


除了检测结果图，脚本还会生成训练曲线图。左边的图展示了训练损失和验证损失随epoch的变化，理想情况下两条曲线都应该下降且差距不大。右边的图展示了验证集F1分数的变化曲线，它应该逐渐上升并趋于平稳。

## 常见问题与解决方案

显存不足（CUDA Out of Memory）是最常见的问题。由于孪生网络需要同时加载两张图像，显存消耗是普通语义分割的两倍。解决方案按优先级排列：减小batch_size（从6降到4或2）；减小img_size（从256降到192或128）；如果仍然不够，可以考虑使用混合精度训练（在Trainer中添加autocast）。

变化区域太少导致模型"偷懒"。如果你发现模型的OA很高（比如98%）但F1很低（比如0.2），说明模型学会了一种"捷径"——把所有像素都预测为"未变化"。这种情况下，需要增大ChangeLoss中的pos_weight参数（默认值为5.0，可以尝试增大到10.0），给变化类别更高的权重，迫使模型关注变化区域。

模型过拟合。如果训练损失持续下降但验证损失开始上升，或者训练集F1很高但验证集F1明显偏低，说明模型出现了过拟合。可以尝试的对策包括：增大数据增强强度、减小模型容量（减少编码器通道数）、增加weight_decay（权重衰减）、增加训练数据量。

合成数据与真实数据的差异。合成数据虽然模拟了变化检测的基本模式，但它与真实遥感影像之间仍有显著差距。合成图像中的建筑是简单的矩形色块，而真实影像是复杂的纹理和结构；合成数据中没有光照差异、季节变化、云层遮挡等真实世界中的干扰因素。因此，在合成数据上训练的模型无法直接迁移到真实影像上——你需要用LEVIR-CD等真实数据集重新训练。

## 使用自己的数据

当你准备好使用自己的双时相数据时，只需要按照以下步骤操作。

首先，准备好你的数据。你需要三组图像：时相A图像（时间T1拍摄）、时相B图像（时间T2拍摄，与A同一地点）、变化标签图（标记出发生变化的像素区域）。三组图像的尺寸必须一致，且A和B必须是精确地理配准的。

然后，按照以下目录结构组织你的数据：

```
data/
├── train/
│   ├── A/        ← 放入时相A的训练图像（PNG或TIFF格式）
│   ├── B/        ← 放入时相B的训练图像
│   └── label/    ← 放入变化标签图（二值图：0=未变, 255=变化）
└── val/
    ├── A/
    ├── B/
    └── label/
```

注意标签图的格式：如果使用PNG格式，变化区域应该是白色（像素值255），未变化区域应该是黑色（像素值0）。代码中会自动做二值化处理（阈值127），所以灰度图或RGB图都可以。

确保同一组数据的三个文件使用相同的文件名。比如`area_001.png`在A、B和label三个目录中都存在。

最后，删除已有的合成数据（或放到备份目录），运行训练脚本即可。代码会自动检测数据格式——如果找到.png或.tif文件，就会使用PIL读取；如果找到.npy文件，就会使用NumPy加载。

## 训练效率优化建议

如果你的训练速度不够理想，有几个方向可以优化。首先是数据加载——将num_workers设为CPU核心数的一半左右，可以加速数据读取。其次是pin_memory——代码中已经设为True，它可以加速CPU到GPU的数据传输。如果你的GPU支持混合精度训练（Ampere架构及以上），可以在Trainer中添加torch.cuda.amp.autocast来减半显存消耗并加速计算。

对于大批量实验，建议将合成数据预先生成并保存为.npy文件（代码已经这样做了），避免每次运行时重复生成。如果需要增加训练数据量，可以修改num_train参数（比如增加到500或1000），合成数据的生成是近乎线性的时间开销。

训练完成后，所有结果文件会被保存到对应的目录中。最优模型权重保存在models/best_siamunet.pth，可视化结果保存在outputs/change_detection_results.png和outputs/training_curves.png。这些文件是你评估模型性能、进行后续推理和部署的基础。
